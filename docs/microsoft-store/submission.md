# Microsoft Store submission

> **Status:** the application is *Store ready* (MSIX packaging, identity, assets and policies are in
> place) but it has **not** been submitted or published. Publication requires a Partner Center account,
> a reserved application name and Microsoft certification. This document lists exactly what remains.

## 1. Package

| Item | Value |
|---|---|
| Package identity name | `DietTracker.Desktop` (in `src/DietTracker.App/Package.appxmanifest`) |
| Publisher | `CN=DietTracker` - **must be replaced** with the Partner Center publisher identity |
| Display name | DietTracker |
| Minimum Windows | 10.0.22621.0 (Windows 11 22H2) |
| Architectures | x64, ARM64 |
| Capabilities | `runFullTrust` only (no restricted capabilities beyond the desktop hosting model) |
| Extensions | `windows.startupTask` (Start with Windows, disabled by default) |

Build the upload artifact:

```bash
dotnet build src/DietTracker.App -c Release -p:Platform=x64 \
  -p:AppxPackageSigningEnabled=true \
  -p:PackageCertificateKeyFile=<path to .pfx> \
  -p:PackageCertificatePassword=<password>
# output: artifacts/msix/DietTracker_<version>_x64_Release/DietTracker_<version>_x64.msix
```

For the Store, **do not** ship your own signing certificate: submit the unsigned `.msix` (or
`.msixupload`) and let the Store sign it. Use `-p:AppxPackageSigningEnabled=false` for that build.

Local validation before submitting:

```bash
# Windows App Certification Kit
"C:\Program Files (x86)\Windows Kits\10\App Certification Kit\appcert.exe" reset
"...\appcert.exe" test -appxpackagepath <path to .msix> -reportoutputpath report.xml

# MakeAppx round trip (structural validation)
"...\makeappx.exe" validate /p <path to .msix>
```

## 3. Certification notes for reviewers

Provide this text in the "Notes for certification" field:

> DietTracker works fully offline and **no account is required**. To test the cloud features, use the
> Account and sync page: sign in with a Google account, then use "Synchronize now".
> Authentication uses the official OAuth 2.0 flow with PKCE in the system browser and never asks for a
> password inside the application. Google Drive storage is limited to the hidden `appDataFolder`. All
> privacy controls (export, local backup, sign out, disable synchronization, delete local data, delete
> cloud data) are on the Settings page.

## 4. Partner Center steps (what remains)

1. Create or configure a **Microsoft Partner Center** developer account (individual or company) and pay
   the one-time registration fee if applicable.
2. Reserve the application name **DietTracker**.
3. Copy the **publisher identity** (Publisher CN, package identity name, package family name) from
   Partner Center into `Package.appxmanifest`.
4. Configure the Google Cloud project (OAuth consent screen, Desktop app client) so that sign-in works
   (see `docs/authentication/setup.md`). Verify with the packaged build.
5. Configure the package: version, architecture, languages, capabilities.
6. Generate the MSIX upload artifact with the Release configuration.
7. Run the Windows App Certification Kit locally and fix anything it reports.
8. Create the submission in Partner Center, upload the artifact, complete the listing and the age
   rating questionnaire, and submit for certification.
9. Review the certification report; fix and resubmit if necessary.
10. Publish updates by uploading a new package with an increased version number (the Store delivers the
    update automatically).

## 5. Updates and user data

* User data lives in the package's private `LocalState` folder (`ApplicationData.Current.LocalFolder`),
  **not** in the installation directory, so Store updates cannot erase it.
* Database schema changes are applied by versioned, transactional migrations with a pre-migration
  safety copy (`VACUUM INTO`) and a post-migration integrity check.
* Uninstalling a packaged application removes its `LocalState` folder; users are therefore advised to
  keep a local backup (`.dtbackup`) or connect an account for recovery. This behaviour is documented in
  the README and in the Settings page wording.
